# Security Policy

AKILTA main is a private proprietary engineering repository.

## Reporting a security issue

Report suspected vulnerabilities, credential exposure, privacy defects, or
security-sensitive design issues through a confidential channel available to
the repository owner/authorized AKILTA security authority.

Prefer GitHub's private Security Advisory / private vulnerability-reporting
workflow when it is available for the repository. If that workflow is not
available, contact the repository owner through an approved private channel.

Do **not** place passwords, API keys, tokens, private keys, customer data,
exploit details, or other sensitive evidence in a public issue, discussion,
ordinary log, or unapproved prompt.

## Current support status

This repository is an engineering source repository. It does not currently
represent a generally available customer-facing production release.

Security claims for a future public/commercial AKILTA release must be based on
the actual shipping architecture, deployment, dependency graph, data flows,
and operational controls at that release.

## Repository handling

- Real secrets must not be committed.
- Third-party or confidential material must not be admitted without a valid
  rights/authority basis.
- Security-relevant changes remain subject to the repository's existing
  authority, review, and evidence rules.
- A material known security/privacy defect that makes an imminent release
  unsafe must fail closed rather than be hidden by documentation.
