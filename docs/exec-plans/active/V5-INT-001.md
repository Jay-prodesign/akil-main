## Goal

Provide a pure, side-effect-free reconciliation function that combines opaque cross-domain evidence pointers ("insights") about the same subject into a governed snapshot, without ever reading or reinterpreting the underlying domain records those pointers reference, and without ever presenting stale or disputed evidence as settled truth.

## Scope (this checkpoint)

- `src/domain/cross-domain-intelligence.ts`:
  - `IntelligenceSourceDomain` — a closed union of exactly the six surfaces the blueprint's §10 text names verbatim (SALES, DELIVERY, OPERATIONS, ENGINEERING, COMMERCIAL, PRODUCT). An insight from any other domain is rejected, not accepted.
  - `IntelligenceInsight` — carries `tenantScope`/`projectRef` (reusing the existing `TenantScope` isolation primitive), `domain`, `subjectRef`, an `IntelligenceEvidenceKind` (`OBSERVED` | `DERIVED`, preserved verbatim through reconciliation — never blurred), an opaque `value` string (never interpreted, only compared for equality), `capturedAt`, and a `sourceRef` pointer to the already-existing typed record it came from (e.g. a `CommercialAuthoritySnapshot` or `OperationsAttentionItem`) — this module never reads that record itself.
  - `buildCrossDomainIntelligenceSnapshot(request)` — pure function. Fails closed (`InvalidCrossDomainIntelligenceRequestError`) on an empty/whitespace `projectRef`, an invalid `asOf`/`capturedAt` timestamp, or a negative `freshnessThresholdMs`. Rejects (into `rejectedInsights`, with a reason) any insight whose `domain` is unrecognized or whose `tenantScope`/`projectRef` does not match the request's own scope. Groups the remaining insights by `subjectRef` and reconciles each group against the caller-supplied `asOf`/`freshnessThresholdMs`: no fresh insight → `STALE` (no `agreedValue`); fresh insights disagree → `CONFLICTING` (no `agreedValue`); fresh insights agree → `CURRENT` (`agreedValue` set).

## Explicitly deferred (not invented)

No filesystem write, no network call, no read of any other domain module's actual records — the module has exactly one import (`TenantScope`, for scope-matching only) and never calls `Date.now()` (freshness is computed only against the caller-supplied `asOf`, keeping the function fully deterministic and replayable). No "strategic company memory" persistence store, no cross-client aggregation across tenants (a request is always scoped to exactly one `tenantScope`/`projectRef`), no automatic reconciliation of a `CONFLICTING` subject — the blueprint's own acceptance language ("conflicting sources remain unresolved until reconciled") is a hard non-goal for this checkpoint to auto-resolve.

## Architecture / semantic invariants (verified by test)

- An insight whose `tenantScope`/`projectRef` differs from the request's is rejected, never included in `reconciled` — no cross-client or cross-project data leakage.
- An insight whose `domain` is outside the closed six-value set is rejected, never included.
- A subject with no insight captured within `freshnessThresholdMs` of `asOf` resolves `STALE` with no `agreedValue` — stale evidence never masquerades as current.
- A subject whose fresh insights disagree on `value` resolves `CONFLICTING` with no `agreedValue` — disagreement is never silently arbitrated.
- `OBSERVED` and `DERIVED` insights are never merged into a single blurred value — every retained insight keeps its own `kind`.
- Distinct `subjectRef`s are reconciled fully independently of one another.

## Hard Non-Scope

No filesystem/network/child_process import (verified by boundary scan); no provider/model hard-coding; no secret/credential material; no `Date.now()` call (verified by boundary scan); no mutation of the domain records an insight's `sourceRef` points to; no merge/deploy/release/production/publication/customer-binding/legal/financial action anywhere in this checkpoint's source.
