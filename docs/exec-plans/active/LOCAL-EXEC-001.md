## Rev101 correction (F1 — device/worker ownership binding; F2 — declared ref list shape validation)

Brain's Rev101 independent exact-head review (fresh-read from the canonical Drive Handoff, `CHANGES_REQUIRED, BOUNDED` against this PR's exact pushed head `01fa311a99106db534b085c5f71578ea44e64f76`) found two genuine gaps in `createLocalWorkerRegistration`:

- **F1**: `ownerMembershipRef` was accepted as an independent caller-supplied string, never checked against `input.device.ownerMembershipRef` — a worker could be registered claiming any owner, regardless of which owner the device itself was enrolled under. Existing tests never exercised this because the shared `makeWorker` test helper always defaulted the override to `device.ownerMembershipRef`, and every test that did pass an explicit override happened to pass the same value the device already had (a genuine coverage gap, not a false negative in the prior tests).
- **F2**: `declaredCapabilityRefs`/`declaredToolRefs`/`declaredPolicyConstraintRefs` were blind-cast (`as ReadonlyArray<string>`) straight from caller input with no shape check, unlike `createDevicePolicy`'s own `allowedWorkspaceRootRefs`, which already validates array-of-non-empty-strings in this same file.

Fix: before any other work, `createLocalWorkerRegistration` now fails closed (`InvalidLocalExecutionError`) whenever the supplied `ownerMembershipRef` does not exactly equal `input.device.ownerMembershipRef` — a fresh repo-wide search for an existing delegation/re-assignment primitive that could instead authorize a genuine owner mismatch found none, so per Rev101's own instruction the self-certification gap is closed by narrowing to fail-closed-on-mismatch rather than inventing a new IAM primitive. A new private helper `requireStringRefArray` (mirroring `createDevicePolicy`'s existing array/non-empty-string-member check exactly, empty array valid) now validates all three declared ref lists before they are projected into the registration or (downstream, unmodified) into `AdmittedWorker`. No existing convention in this codebase dedupes such ref lists (`worker-routing-policy.ts` only ever tests membership via `.includes()`/`includesAll`), so duplicates are left as supplied rather than silently dropped.

New tests: L42 (adversarial A-device/B-worker-owner substitution fails closed), L43 (matching owner still succeeds), L44 (non-array ref list on any of the three fields fails closed), L45 (a non-string/empty-string member fails closed, while an empty array is accepted). Sanity-checked: the fix was temporarily reverted via `git stash` while the updated test file was kept — exactly L42/L44/L45 failed (L43, the positive case, still passed) — confirming the tests genuinely detect both gaps; the fix was then restored and 759/759 reconfirmed.

No exported symbol was added or removed (`requireStringRefArray` is a private, unexported helper), so `tests/local-exec-001-boundary-scan.test.ts`'s "exact expected surface" assertion required no update.

## Architecture / semantic invariants (verified by test)

Every one of the packet's ten mandatory acceptance cases (§22 A-J) is directly proven:

- **B (Local OFF)**: `CLOUD_NORMAL` excludes every local worker unconditionally, regardless of registrations supplied (L21).
- **C (employee isolation)**: `PERSONAL_LOCAL` admits only the requester's own `PRIVATE`-pool worker, never another owner's (L22-L23).
- **D (independent projects)** / **E (shared project opt-in)**: `TEAM_LOCAL` admits an `ORG_POOL` worker only when actually bound to the target project ownership tuple (L25-L26).
- **F (failover)**: a `DEGRADED` primary is skipped and an equally-authorized `AVAILABLE` fallback is selected through the existing, unmodified `resolveWorkerRoute` with no authority relaxation (L31).
- **G (revocation)**: `REVOKED` is permanently terminal on a device; a lease can never be created against a non-`ONLINE` device (L8, L32).
- **J (adversarial device channel)**: cross-tenant worker substitution (L28, sanity-checked — see Evidence), a worker/device `deviceId` mismatch (L33), an unauthorized workspace root (L15), and (Rev101 F1) an A-device/B-worker-owner substitution (L42, sanity-checked) all fail closed.
- **A/H/I** (personal zero-manual-key path, provider-policy gate, unknown external effect) are structural properties of later phases (L2/L5/L6, and the already-built `V4-EFF-001` envelope respectively) rather than this floor's own testable surface, and are not fabricated here.
- The composition proof (L30): a `LocalWorkerRegistration`, gated through `resolveEligibleLocalWorkers`, routes successfully through the completely unmodified `resolveWorkerRoute` — no second routing engine exists anywhere in this module (boundary-scan test additionally asserts no `LocalWorkerRouter`-shaped symbol is defined).
- Every `LocalTaskLeaseStatus` transition is validated against a strictly closed graph — no direct `QUEUED`→`SUCCEEDED` jump, and no transition is ever permitted out of a terminal status (L35-L37, L39).
