## Explicitly deferred (not fabricated)

- **No decide/complete/deny control.** Completing or denying a `CustomerOffboardingRequest` from this surface requires both an authenticated admin-mutation boundary (the `connector-connection-admin-access.ts` pattern) and a durable store for the request itself — neither exists, and inventing a new durable store is explicitly outside "the smallest coherent reversible packet" this checkpoint scopes to. A future checkpoint may close this once a request store is separately authorized.
- **No "subscription/entitlement/billing-reference state counts" aggregation.** An earlier, broader research pass suggested this as part of the same gap; it was deliberately narrowed out of this checkpoint because it requires a "list all customers under this tenant" capability this repository does not have today, and because the pending-offboarding-queue gap is the one with a concretely identified FUNCTIONAL necessity (a staff decider needs something to decide on), not merely descriptive value. May be picked up as its own later checkpoint if a fresh scan still finds it open.
- **No production-shaped implementation of the new port.** Only test fixtures exist (mirroring every other optional port in this repository's Admin composition); a real store-backed implementation is a separate, later integration step.
