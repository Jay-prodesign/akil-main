## Goal

Every individual failure mode REV209 names here was already certified, one at a time, by a prior V0 or V1 package. This task closes exactly that composition gap.

## Design decisions and why

- **`CHAOS1` is the one genuinely new composed scenario**: a SINGLE `Promise.all` combining tenant A's and tenant B's own quota fan-out races (different ceilings, on a SHARED `FileDurableQuotaReservationStore` instance), their own configuration-policy rollbacks (colliding bare `decisionKey` identifiers, on a SHARED `FileDurableConfigurationPolicyDecisionStore` instance), and a break-glass foreign-org-visibility attempt — all resolving at the exact same wall-clock moment. Every one of these primitives already proved pairwise/sequential isolation; this proves it holds when several are stressed TOGETHER, which is the literal meaning of "concurrently across organizations" that no prior round tested.
- **Every other new test is a smaller, two-tenant `Promise.all` composition** of one already-certified primitive — not because the primitive needs re-proving, but because REV209 explicitly asks for these specific failure modes to be exercised "concurrently across organizations," and a sequential (not `Promise.all`'d) pairwise test would not actually demonstrate that.
- **"Stale cache/index" is honestly disclosed `NOT_APPLICABLE`, never manufactured** — mirroring OS-V1-03's own identical finding and REV209's own explicit "do not manufacture unactivated capabilities" instruction.
