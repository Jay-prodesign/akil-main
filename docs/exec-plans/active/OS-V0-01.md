## Minimum Organization semantics

- Immutable `Organization` identity: `organizationId`, exact `tenantId` from a supplied `TenantScope`, `displayName`, lifecycle `state`, and caller-supplied lifecycle timestamps only.
- Minimal V0 lifecycle: `BOOTSTRAPPING → ACTIVE → SUSPENDED`. `BOOTSTRAPPING` is construction/bootstrap; `ACTIVE` is normal usable state; `SUSPENDED` is a controlled stop. No reactivation API — V1 owns richer suspend/reactivate/offboarding semantics.
- Creation always starts `BOOTSTRAPPING`; callers cannot forge an initial `ACTIVE`/`SUSPENDED` state.
- Activation is only `BOOTSTRAPPING → ACTIVE`. Suspension is only `ACTIVE → SUSPENDED`. Invalid/stale/double transitions fail closed. Transitions are immutable (return a new value) and preserve identity/tenant/display-name provenance.
- Lifecycle timestamps must be valid instants and chronologically monotonic; no `Date.now()`/`new Date()` implicit clock, no randomness — mirrors `service-catalog-admission.ts`'s `requireValidTimestamp` (parse via `Date.parse`, compare by `ms`, never raw string).
- Organization Zero is evidence, not a privileged code path: tests construct `org_akilta` and at least one controlled second Organization through the identical public factory/transition functions — no `isSystem`/`isPlatform`/bypass/superuser flag, no `OrganizationZero`-only constructor, no hidden authority grant.
