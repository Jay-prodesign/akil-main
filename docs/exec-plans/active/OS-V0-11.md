## Goal

Add a durable, explainable, rollback-capable **decision projection** on top of the existing, unmodified `resolveEffectiveConfigurationPolicy` resolver, for an exact scope identity (tenant/customer/project/job/action). The projection must: (1) persist every genuinely new resolution with full version/provenance (the exact controls snapshot that produced it, plus when); (2) detect staleness against the prior persisted decision and explain exactly which `kind`+`key` changed between which two controls; (3) support safe rollback to any prior recorded decision without ever mutating or deleting history, gated by the same ordinary-EXECUTE + protected-action authority pairing this codebase already establishes for every other protected mutation. Prove, via one real integration witness, that the existing V0 consumer (`organization-resource-binding.ts`'s currentness gate) accepts this packet's `resolution.effectiveConfigRefs`/`effectivePolicyRefs` output unchanged, and that a drifted decision's explanation lines up with that gate's own independently-detected staleness — without modifying `organization-resource-binding.ts`'s own source.

## Semantics

- **Identity and keying.** `ConfigurationPolicyDecisionIdentity` mirrors the resolver's own scope-identity shape (`tenantId` required; `customerId`/`projectId`/`jobId`/`actionRef` optional, each only meaningful if the deeper field it implies is also supplied). `encodeConfigurationPolicyDecisionKey` is the SAME collision-safe `JSON.stringify`-of-ordered-tuple convention this codebase already uses everywhere (`effectiveRef`, `quotaScopeKey`, `computeConnectorEffectFingerprint`, etc.) — a decision's durable partition key, never an opaque string concatenation.
- **Computation (`computeConfigurationPolicyDecisionProjection`).** Calls `resolveEffectiveConfigurationPolicy` verbatim with the identity's own fields plus caller-supplied `controls` — never a second resolution policy, never a duplicated precedence/protected-floor/scope-correlation check. Wraps the result with `decisionId`/`computedAt`/`inputControlsSnapshot`/`entryKind: "COMPUTED"`. Every one of the resolver's own fail-closed errors (malformed control, protected-floor override attempt, scope-correlation failure, etc.) propagates unchanged.
- **Equality and drift.** `configurationPolicyResolutionsEqual` is a deep, order-independent comparison over `effectiveControls` (the richer provenance shape — never the derived ref strings alone, since those are one-to-one with it). `describeConfigurationPolicyDecisionDrift` reports, per distinct `kind`+`key`, the previous and fresh `EffectiveControl` (either side `undefined` when that key did not exist there) — "effective-value explanation," never a bare changed/unchanged boolean.
- **Durable append log (`DurableConfigurationPolicyDecisionStore`).** Per `decisionKey`, an open-ended append-only history — unlike `DurableProtectedDecisionRecordStore`'s "created once, revised at most once" contract, a config/policy decision is EXPECTED to change repeatedly over its lifetime. `appendDecisionProjection` is single-use PER `decisionId` (the same proven atomic `linkSync`-hardlink claim pattern, idempotent on identical replay, a hard conflict on same-id/different-content). `getActiveDecisionProjection` is "latest wins over the full append log" (mirroring `getDecisionRecord`'s own discipline) — the most-recently-appended entry is always current. `getDecisionProjectionHistory`/`getDecisionProjectionById` give full readback for audit/explainability and rollback-target lookup.
- **Orchestration (`resolveAndProjectConfigurationPolicyDecision`).** Resolves fresh, reads the currently active entry, and appends a new `COMPUTED` entry ONLY if the fresh resolution differs from the active one (idempotent no-op otherwise, returning the existing entry unchanged) — the append log is a true replay log, never padded with no-op writes. Returns `{ resolution, entry, stale, drift }`: `stale` is `true` only when a prior decision existed AND differed; `drift` is always computed relative to whatever the prior entry was (or `undefined` on a genuinely first decision, in which case every fresh control is reported as newly established, for audit completeness).
- **Rollback (`rollbackConfigurationPolicyDecision`).** NEVER mutates or removes history — always appends a NEW `ROLLBACK` entry whose `resolution`/`inputControlsSnapshot` are copied verbatim from the target entry, with `rolledBackToDecisionId` recording exactly which prior decision this reverts to. Requires `requireSameTenant` + `requirePermission(authority, "EXECUTE")` + `requireProtectedActionAuthorization` — the SAME ordinary-EXECUTE-plus-protected-action pairing this codebase already establishes for every other protected mutation (the Rev186 Founder clarification), since a rollback can resurrect a stale or previously-superseded control selection and is therefore materially impactful. Targeting a `decisionId` that was never recorded throws `ConfigurationPolicyDecisionNotFoundError` before any append.
- **Integration witness.** `tests/organization-resource-binding.test.ts` proves `resolveAndProjectConfigurationPolicyDecision`'s `resolution.effectiveConfigRefs` feeds `resolveOrganizationResourceBindingStatus`'s `currentEffectiveConfigRefs` byte-for-byte (a binding built from the first decision resolves `READY`), and that a second, materially drifted decision's own refs reproduce exactly the SAME `CONFIG_NOT_CURRENT` the binding's existing, unmodified currentness gate independently detects — the durable drift explanation and the pre-existing opaque-ref currentness check agree without either depending on the other's internals.

## Rev193 correction round

- **Finding**: `rollbackConfigurationPolicyDecision` resurrected a target entry's historical resolution without checking whether a PLATFORM `protectedFloor` control had been established or changed since that target was computed — silently weakening a non-weakenable floor would violate this packet's own "lower scope may not weaken protected higher scope" invariant (Rev141/Rev192).
- **Fix**: added a required `currentControls` input to `rollbackConfigurationPolicyDecision`. Before any append, the current controls are resolved via `resolveEffectiveConfigurationPolicy` verbatim (never a second resolution policy) into `currentResolution`, then `findProtectedFloorConflicts(target.resolution, currentResolution)` reuses the existing `describeConfigurationPolicyDecisionDrift` helper (never duplicated comparison logic) filtered to drifts where the CURRENT winning control is itself `scope: "PLATFORM"` and `protectedFloor: true`. An ordinary (non-floor) drift between target and current state is not disqualifying — resurrecting a stale ordinary-scope selection is rollback's whole purpose. The return type widened to a discriminated union: `{ kind: "ROLLED_BACK", entry }` or `{ kind: "BLOCKED_PROTECTED_FLOOR_CONFLICT", conflicts }` — a conflict returns zero mutation, history and active entry left exactly as they were.
- **Tests**: two new adversarial tests added to `tests/resolve-and-project-configuration-policy-decision.test.ts` — (1) a newer PLATFORM protected-floor control established after the target decision blocks the historical rollback, asserting the exact conflicting `kind`/`key`/`sourceRef`, zero history growth, and an unchanged active entry; (2) a historical rollback target that drifts from current controls only in an ordinary (non-floor) way still succeeds normally. Existing O4–O8 updated to supply `currentControls` for the new required parameter and to unwrap the `ROLLED_BACK` discriminant.
- **Guard-disable sanity**: the new `if (conflicts.length > 0)` check was disabled (`if (false && conflicts.length > 0)`); rebuild + focused run reproduced exactly the predicted single failure (the new "Rev193 adversarial" test) and nothing else (10/11 passing, 1 failing as predicted); the guard was then restored and the focused suite re-ran fully green (11/11).
- **Boundary scan**: `tests/os-v0-11-boundary-scan.test.ts`'s import-line assertion for `resolve-and-project-configuration-policy-decision.ts` updated to match the new `resolveEffectiveConfigurationPolicy` runtime import (previously type-only); export-surface assertion unchanged (the new result type is erased at runtime).
- **Full regression**: `node --test dist/tests/*.test.js` — **2463/2463 passing** (2461 prior + 2 new Rev193 tests).
- **Scope**: per Rev193's own dispatch, this round is focused typecheck/tests + exact-head CI only — no broader adversarial/integrated audit was performed or required this round (Founder finish-first cadence).
