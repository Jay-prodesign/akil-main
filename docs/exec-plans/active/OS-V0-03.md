## Goal

Close the plan-admission durable-replay isolation gap: treat every persisted `PlanAdmissionEvent` line as untrusted replay input, and fail closed — before the pure reducer ever sees it — whenever a persisted event's own identity fields (or, for `EVALUATION_RECORDED`, its nested `PlanAdmissionResult`'s identity/version) do not exactly match the tenant/customer/project/plan tuple the caller actually requested. Preserve every existing legitimate restart/replay/idempotency/out-of-order/duplicate-answer behavior unchanged. Separately, produce a fresh, read-only inventory of every other persistence/runtime plane materially activated by the current V0 golden path, classifying each as SATISFIED / GAP / DEFERRED-BY-ACTIVATION, as a precise map for later OS-V0-03 phases — without fixing any of those other planes in this packet.

## Semantics

- `validatePersistedPlanAdmissionEvent(raw, expected)` is invoked for every line `getEvents` reads, before any event reaches the reducer. `expected` is the exact `{tenantId, customerId, projectId, planId}` tuple the caller passed to `getEvents`/`getState` — never a value read from the persisted data itself.
- Every persisted event must be a recognized `EVALUATION_RECORDED` or `ANSWER_RECORDED` object shape; `eventId`/`recordedAt` must be non-empty, non-whitespace-padded strings; `planVersion` must be a positive integer. Any violation throws `CorruptedPlanAdmissionEventError` (fail-closed) — nothing is silently dropped, coerced, or partially accepted.
- The event's own `tenantId`/`customerId`/`projectId`/`planId` must exactly equal the requested tuple ("envelope scope" gate) — this is what stops a foreign-scoped FIRST event from ever reaching the reducer and constructing foreign state.
- For `EVALUATION_RECORDED`, the nested `result`'s `tenantId`/`customerId`/`projectId`/`planId`/`planVersion` must exactly equal the event envelope's own identity/version ("nested-result correlation" gate) — an independent, overlapping check from the envelope-scope gate (guard-disable sanity proved both are independently load-bearing: disabling either one still leaves the other catching most cross-scope forgeries; only the envelope gate catches an `ANSWER_RECORDED`-type forgery, since that event type has no nested result to cross-check). `result.status` must be a recognized `AdmissionStatus` (`ADMITTED`/`BLOCKED`/`WAITING`).
- For `ANSWER_RECORDED`, `answeredEntity` must be a non-empty, non-whitespace-padded string. No business-level admission authorization is performed here (that remains `recordAnswer`'s job, unchanged) — this task hardens persistence integrity/isolation only, per Rev137's explicit instruction not to alter `applyPlanAdmissionEvent` business semantics.
- Explicitly deferred (not this packet, not this file): `FileDurableOutcomeJobStore`'s equivalent blind-cast gap, `FileDurableEngineeringStore`'s equivalent blind-cast gap (see Inventory table below) — both recorded as named next-gap candidates, not fixed here, per Rev137's read-only-inspection-only authorization for every plane outside `durable-plan-admission-store.ts`.
