## Scope (this checkpoint)

- `src/domain/external-effect-envelope.ts`:
  - `ExternalEffectIntent`/`createExternalEffectIntent` — "proposed effect/action intent, scoped authority/approval requirement, idempotency/retry classification." `actionRef` is an opaque pointer (never interpreted, matching `connector-execution.ts`'s own "capabilityRef is opaque" discipline). `retryClassification` (`SAFE_TO_RETRY`/`NOT_SAFE_TO_RETRY`/`REQUIRES_MANUAL_REVIEW`) is caller-declared at creation time — this module never infers it.
  - `ExternalEffectAttempt`/`startExternalEffectAttempt` — begins an attempt at `NOT_STARTED`. When `intent.requiresApproval` is true, a granted, same-tenant, protected-action-authorized `AuthorityContext` plus a non-empty `evidenceRef` are mandatory before an attempt can even start; the evidence is carried forward on the attempt as `approvalEvidenceRef`.
  - `reportExternalEffectOutcome` — "external correlation/effect attempt." Records `APPLIED`/`FAILED`/`UNKNOWN`, always requiring a non-empty `externalCorrelationRef` (even for `UNKNOWN` — an inconclusive attempt still needs something concrete for later reconciliation). Callable only once per attempt from `NOT_STARTED`.
  - `verifyExternalEffectReadback` — "post-action verification/readback evidence." Only an independent readback that actually confirms the effect took hold can move an `APPLIED` attempt to `VERIFIED`; if the readback disproves it, the attempt is corrected to `FAILED` rather than left falsely `APPLIED` — readback evidence is always authoritative over the originally claimed outcome.
  - `retryExternalEffectAttempt` — "UNKNOWN fail-closed/no blind retry." The only way out of `FAILED`/`UNKNOWN`, and it never mutates the existing attempt in place — a retry mints a genuinely new attempt id. Fails closed unless the intent's own `retryClassification` is exactly `SAFE_TO_RETRY` (`NOT_SAFE_TO_RETRY`/`REQUIRES_MANUAL_REVIEW` can never be programmatically retried by this function, regardless of authority — a human must start an entirely new intent from scratch), a granted same-tenant protected-action-authorized authority is supplied, and a non-empty `evidenceRef` justifies it.
  - `rollbackExternalEffectAttempt` — "rollback/recovery capability where available." A governed, explicit undo of an `APPLIED` or `VERIFIED` attempt, terminal state `ROLLED_BACK`, distinct from `FAILED` (a rollback undoes something that DID apply; a failure never applied).
  - `isRecognizedExternalEffectAttemptState` — exported fail-closed type guard for a future durable store to reuse (no store built in this checkpoint — no caller exists for one yet, so none is fabricated).
- `tests/external-effect-envelope.test.ts` (28 tests: E1-E28) and `tests/v4-eff-001-boundary-scan.test.ts` (6 tests).

## Explicitly deferred (not invented)

- **No durable store.** This checkpoint is the pure state-transition contract only; no `FileDurable*`/persistence adapter is built, since no real caller (a real connector adapter or service-specific control adapter) exists yet to consume one — matching this repository's own progressive-elaboration discipline of not building speculative plumbing ahead of an actual caller.
- **No real provider mutation.** `reportExternalEffectOutcome`/`verifyExternalEffectReadback` accept caller-supplied outcomes/readback results; this module never makes an HTTP call, never touches `node:https`, and is never wired to any specific connector.
- **No second approval ledger.** `startExternalEffectAttempt`'s approval requirement reuses `authority.ts`'s existing `AuthorityContext` gate directly rather than inventing a parallel durable approval record — a caller that needs a full approval audit trail already has `approval-reference.ts`.
- **No wiring into CONN-001's `connector-execution.ts` or SALE-TO-CLOSE's `outcome-job.ts`.** Both are existing, in-review/merged modules with their own governed scope; this checkpoint deliberately stays a standalone, reusable envelope rather than modifying either.

## Architecture / semantic invariants (verified by test)

- An approval-required intent cannot start an attempt without a granted, same-tenant, protected-action-authorized authority and non-empty evidence (E4-E7).
- Every reported outcome — including `UNKNOWN` — carries a mandatory external correlation reference; an outcome can only ever be reported once per attempt (E8-E11).
- A readback disproving a claimed `APPLIED` outcome corrects the attempt to `FAILED`, never leaving it falsely `APPLIED` (E13); readback verification is only ever accepted from `APPLIED` (E14).
- `UNKNOWN` is never silently retried — `retryExternalEffectAttempt` is the only exit, and it fails closed on a `NOT_SAFE_TO_RETRY`/`REQUIRES_MANUAL_REVIEW` intent regardless of how strong the supplied authority is (E16-E17, sanity-checked — see Evidence), on a non-`FAILED`/`UNKNOWN` attempt (E18), on a cross-tenant or non-protected-action authority (E19-E20), on a reused `attemptId` (E21), and on a mismatched intent/attempt pair (E22).
- `rollbackExternalEffectAttempt` only accepts `APPLIED`/`VERIFIED` attempts (never `NOT_STARTED` — nothing to roll back) and requires the same authority discipline (E25-E26).
- The full happy-path chain (start → report `APPLIED` → verify → `VERIFIED`) preserves `effectIntentId`/`tenantId`/`externalCorrelationRef` throughout and never regresses to an earlier state (E28).
