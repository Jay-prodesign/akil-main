## Goal

Model responsibility correctly across the commercial-to-delivery lifecycle: `LeadOwner`, `DealOwner`, `AccountOwner`, and `DeliveryOwner` as independent, provenance-preserving assignments over an ownership scope (`ProjectOwnershipRef`) and an organization member (`OrganizationMembership`, V3-ORG-001) — without granting any transition/approval authority over `OutcomeJob`/`ProjectPlanVersion`.

## Scope (this checkpoint)

- `OwnerRole` (`LEAD_OWNER | DEAL_OWNER | ACCOUNT_OWNER | DELIVERY_OWNER`) + `OwnershipAssignment` + `createOwnershipAssignment` (`src/domain/ownership-assignment.ts`).
- `reassignOwnership` — provenance-preserving reassignment: returns a `superseded` copy of the prior record (never mutated/erased) plus a `next` record that preserves the exact `ownership`/`ownerRole` scope, changing only the assignee.
- `resolveCurrentOwner` — canonical current-owner resolution from a caller-supplied history array; returns `undefined` (not a guess) when no active record exists, and fails closed (throws) on a data-integrity ambiguity (more than one active record for the same scope/role) rather than silently picking one.

## Architecture / semantic invariants

- One membership may hold multiple owner roles (or the same role on multiple projects) via multiple distinct `OwnershipAssignment` records — never a multi-value field on one record — so "one role never implies another" is structural.
- `createOwnershipAssignment` rejects when `membership.tenantId !== ownership.tenantId` — a membership foreign to the ownership scope's tenant is contamination, not silently accepted (§5 "invalid/foreign owner reference fails closed").
- `reassignOwnership` rejects cross-tenant reassignment and rejects reassigning an already-superseded record (stale-assignment protection); the returned `next` record reuses the prior record's `ownership`/`ownerRole` verbatim, so scope cannot drift during reassignment.
- No mutation in place anywhere: `reassignOwnership` never modifies its `priorAssignment` argument — verified by a functional test asserting the original object's `supersededAt` remains `undefined` after the call.
- This module imports nothing from `outcome-job.ts`, `project-plan.ts`, or `approval-reference.ts` — an `OwnershipAssignment` cannot itself transition an `OutcomeJob` or approve a `ProjectPlanVersion` (verified by boundary-scan import check).
- Reuses `ProjectOwnershipRef` (V2-CDO-003) and `OrganizationMembership` (V3-ORG-001) directly by type import — no parallel ownership-scope or membership identity was created.
