## Design decisions and why

- **Every `StaffSessionContext` lifecycle field is OPTIONAL, not required.** There is no factory function for this type (unlike `OrganizationMembership`); ~20 existing test files across this repository construct it as a plain `{ principal, issuedAt }` literal. A required new field would silently break every one of them. An absent `state` reads as `"ACTIVE"` and an absent `expiresAt` reads as "never expires" — behaviorally identical to the pre-OS-V1-02 contract for every caller that does not opt in.
- **An expiring session with no `now` supplied fails CLOSED, never open.** `isStaffSessionContextActive` returns `false` whenever `expiresAt` is present but `now` is not — "an expiring session demands a clock to admit it," never a silent bypass.
- **Expired/revoked sessions collapse into the exact same `StaffUnauthenticatedError` as "no session at all."** Mirrors `requireStaffSession`'s own pre-existing doc comment ("sessionToken===undefined and token does not resolve to a session are both, deliberately, exactly the same outcome") — distinguishing "revoked"/"expired" from "never existed" would leak session existence to an unauthenticated caller.
- **"Recovery" is always a fresh session, never a resurrection.** No reactivate/renew function is implemented or exposed for `StaffSessionContext`, matching the "no reactivation" precedent already established for `OrganizationMembership`/`OrganizationServicePrincipal` revocation. Proven directly by W6 in `tests/staff-session-lifecycle.test.ts`: a revoked token never resurrects, but the same principal authenticating fresh under a new token succeeds immediately.
- **The `now` parameter threaded through `requireInternalOsAccess` and its three web wrappers is optional and purely additive** — zero behavior change for any existing caller/test that doesn't pass it, since every existing fixture carries no `expiresAt`.
- **Naming collision avoided deliberately**: `resume-protected-decision-admin-access.ts`'s own `DomainInput` already has a REQUIRED `now: unknown` field (used for the resume decision's own `resolvedAt`/`occurredAt` timestamp, unrelated to session admission). The new session-admission clock on that one wrapper is named `sessionNow`, not `now`, to avoid silently conflating two unrelated caller-supplied clock values. (Confirmed this was a real risk, not a hypothetical one: an initial draft that spread `input.now` directly into both purposes was caught by `tsc --noEmit` reporting a missing required `now` property once the collision was corrected by destructuring it away.)
- **`DelegatedAccessGrant` composes, does not reinvent.** It holds no role, no policy language, no inheritance graph — a single flat evidence record resolved by one pure, deterministic, explainable function (`resolveEffectiveDelegatedAccess`), mirroring `resolveEffectiveOrganizationAccess`'s own ordered-gate style exactly. `expiresAt` is mandatory (unlike `StaffSessionContext.expiresAt`) because "temporary" is this type's entire reason to exist.
- **No escalation at mint time**: `createDelegatedAccessGrant` rejects any `permissions`/`canPerformProtectedActions` value the delegator's own current `AuthorityContext` does not itself hold, and refuses a revoked/incoherent delegator membership (mirrors `createOrganizationAccessRoleContext`'s own precedent).
- **The load-bearing fix for "stale delegated authority"**: `resolveEffectiveDelegatedAccess` does not and cannot re-derive the delegator's current standing itself (it has no membership/store dependency) — the CALLER must supply a freshly re-resolved `delegatorCurrentAccess` (`EffectiveAccessResolution`), exactly like every other "re-resolve fresh immediately before granting" primitive in this repository (`requireInternalOsAccess`, `authorizeProtectedDecisionResume`, `resolveControlledOrganizationSwitch`). The function then requires `delegatorCurrentAccess.decision === "GRANTED"` AND `delegatorCurrentAccess.membershipId === grant.delegatorMembershipId`, and clamps the effective permission set to the INTERSECTION (never the union) of the grant and the delegator's current authority. A delegator whose own membership is later revoked, or whose own authority has shrunk, can never have the delegation retain the old, now-stale power — even though the grant record itself is still unexpired and unrevoked (W10).
- **Cross-identity and cross-organization substitution both fail closed**: exact `grant.delegatePrincipalRef === currentPrincipalRef` equality (W8) and exact `grant.organizationId === organization.organizationId` / `grant.tenantId === organization.tenantId` correlation (W9), mirroring the same structural-substitution closures `resolveEffectiveOrganizationAccess` already established for membership/principal.
