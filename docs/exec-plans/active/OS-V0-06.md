## The live gap (packet's own finding, confirmed by direct inspection at this head)

`executeConnectorCapability` (`src/domain/connector-execution.ts`) consumed a caller-supplied `BoundConnectorDefinition` whose `ConnectorConnectionInstance` could be stale: it checked that the *supplied* snapshot said `VERIFIED`, but never re-read the current durable connection from `durable-connector-connection-store.ts` before resolving the secret and invoking transport. Concretely, this sequence was architecturally possible before this correction:

1. a caller retains a `VERIFIED` instance bound to `secretRef A`;
2. the durable current connection is later `DEGRADED`/`REVOKED`, or its secret is rotated to `secretRef B`;
3. the stale caller still supplies its old `VERIFIED` object;
4. execution validated the stale object and could resolve `secretRef A` and invoke transport — even though the connection is no longer actually current.

This is the same class of defect as OS-V0-05 Rev167 F20 ("always re-check freshly loaded durable state before any effect"), now closed for connector execution.

## What changed in `connector-execution.ts`

`executeConnectorCapability` gained one new required parameter, `connectionStore: CurrentConnectorConnectionReader` — a narrow `Pick<DurableConnectorConnectionStore, "get">` (read-only; this module gains no `save`/`list` authority). The caller-supplied `input.bound.instance` is now **context only** (it names which `connectionBindingId`/connector definition the caller intends), never authority. On every call:

1. **MUST 1/8** — the current durable record is re-read fresh via `connectionStore.get(requestingOwnership.tenantId, connectionBindingId)`. Missing record → fail closed (`ConnectorExecutionNotAuthorizedError`), zero secret resolution, zero transport call.
2. **MUST 1** — the CURRENT record's own `binding.ownership` (never the caller's stale one) must match `requestingOwnership` exactly (tenant+customer+project+service). Mismatch → fail closed.
3. **MUST 5** — the CURRENT record's `connectorKind` must still match what the bound definition was constructed against (the caller-supplied instance's own `connectorKind`, which `bindGenericApiDefinition`/`bindPrebuiltDefinition` already tied to the definition at bind time) — closing "a stale definition/binding pairing silently switches provider."
4. **MUST 2/3** — only a CURRENTLY `VERIFIED` state may execute. `REQUESTED`/`CONNECTED_UNVERIFIED`/`DEGRADED`/`REVOKED`/`HANDOVER_COMPLETE` all fail closed, using the fresh state — a caller's stale `VERIFIED` snapshot can never survive a later revoke/degrade/rotation.
5. **MUST 4/7** — the secret resolver receives only the CURRENT record's `secretRef`; a stale caller-supplied `secretRef` is never used. Missing current `secretRef` fails closed before transport, exactly as before.
6. **MUST 6** — `capability-admission.ts`'s `CapabilityAdmission` (including a `VERIFIED_AVAILABLE` one) is never accepted as an input to this function at all, so it structurally cannot substitute for the fresh check above — proven by witness R8.
7. **MUST 9** — no protected activation: this slice uses the same mock/injected `SecretResolver`/`ConnectorTransport` boundary as before; zero real OAuth/HTTP/credential/spend code was added.

Every other check (endpoint resolution, transport invocation, response handling, secret-leak-free result shape) is unchanged from the prior accepted implementation.

## Rev172 correction (independent exact-head review of `bc32afc`) — F1: prototype-safe durable dictionary representation

**Finding.** Brain Rev172's independent review of PR #111 exact head `bc32afccb36d7650b4079fe9a5256ff57d5b0ec7` (base `8d5694e7ce2010f66ae18a2d50f7b2e3a2f2481c`, exact-head CI run `36527637196` = SUCCESS) returned CHANGES_REQUIRED: the fresh durable re-resolution added above is directionally correct, but `FileDurableConnectorConnectionStore` — now a load-bearing authority source for every execution decision — still represented its in-memory record dictionary as a plain object literal (`{}`) indexed by the bare, caller-supplied `connectionBindingId` string. Legal binding-id values such as `"__proto__"` or `"constructor"` do not hit ordinary own-property semantics on a plain object: `dict["__proto__"] = value` invokes the inherited legacy `Object.prototype.__proto__` accessor setter and silently changes the object's own `[[Prototype]]` instead of creating an own property (so the record never appears in `JSON.stringify`/`Object.entries` and is effectively lost), while `dict["constructor"]` read on a key that was never actually set returns the inherited `Object` constructor function rather than `undefined` — breaking this store's fail-closed "unknown record" contract and the exact-ownership colliding-binding check `save()` depends on.

**F1 bounded correction.** `durable-connector-connection-store.ts`'s `readAll()` now constructs its dictionary via `Object.create(null)` instead of an object literal, for both the empty-file case and the populated-file case. An object with no `[[Prototype]]` at all has zero inherited members to accidentally match and no `__proto__` accessor to intercept assignment — every bracket get/set on it is a genuine own-property operation for any string key, with no special casing required anywhere else. `save()`/`get()`/`list()` all consume the object `readAll()` returns, so this single representation change closes the gap everywhere at once; every version/ownership/replay/lock/currentness semantic is unchanged, exactly matching the bounded scope Rev172 specified ("Make only the durable connector record dictionary representation prototype-safe, reusing the existing store").

**New tests** (`tests/durable-connector-connection-store.test.ts`): `P1` (adversarial — `get()` for a never-created `"__proto__"`/`"constructor"`/`"toString"`/`"hasOwnProperty"` binding id returns `undefined`, not an inherited member), `P2` (`save()`/`get()` round-trips correctly for each prototype-shaped id plus an ordinary key, with no cross-contamination), `P3` (`list()` includes every one of those ids as a distinct record — a silently-vanished `"__proto__"` write would under-count here), `P4` (restart-safety — a fresh store instance over the same directory reconstructs every prototype-shaped id's record and version identically). One additional real-store witness (`tests/connector-execution.test.ts`, `R13`) proves a `"__proto__"`-keyed connection round-trips through the real `FileDurableConnectorConnectionStore` and executes successfully end-to-end via `executeConnectorCapability`'s own currentness re-resolution path, including surviving a simulated restart — proving the fix holds at the actual call site this whole task exists to protect, not just in isolation against the store.

**Guard-disable sanity.** Reverting `readAll()`'s two `Object.create(null)` calls back to plain object literals reproduces failures in exactly `P1`, `P2`, `P3`, `P4`, and `R13` (the newly load-bearing prototype-safety guard) while leaving every pre-existing test green, then the fix was restored and the full suite reconfirmed passing.

**Validation.** Full regression, strict `tsc` build, and the CONN-001 boundary scan were all re-run green after this correction (see the commit's own exact counts). No new runtime dependency; no other file in the reused primitive set (`connection-authority.ts`, `integration-connector-catalog.ts`, `capability-admission.ts`, `connector-execution.ts`'s own currentness logic from the prior round) was touched — this correction is scoped to exactly the one representation defect Rev172 named.
