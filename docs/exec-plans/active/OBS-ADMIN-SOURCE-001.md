## Scope (this checkpoint)

- New `src/web/operational-observability-admin-source.ts`: `createDurableOperationalObservabilitySource(store: DurableConnectorConnectionStore): OperationalObservabilitySource`. `resolveView(organization)` maps `store.list(organization.tenantId)` into `ConnectionBinding[]` and composes them via `composeOperationalObservabilityView({ connections })`. The `task`/`quota`/`pendingApprovals`/`auditEvidence` dimensions are deliberately left absent (not fabricated as empty-with-false-confidence; the composer's own contract already treats every dimension as independently optional/empty by construction — see "Explicitly deferred").
- The one genuinely novel guard: `resolveView` catches any exception from `store.list` (e.g. a corrupted tenant file) and degrades to an empty-but-valid view, since `resolveOperationalObservabilityView` does not itself catch exceptions from a wired source — mirrors `resolvePendingOffboardingRequestsView`'s own established "a throwing source degrades to the safe default rather than propagating" precedent, applied here at the adapter boundary instead of the resolver boundary (the resolver itself is not touched).
- Tests: `tests/web-operational-observability-admin-source.test.ts` (new, 5 tests) — real connection surfaced; `REVOKED` connection surfaces `killSwitchEngaged: true`; empty tenant (never bootstrapped any connection) returns a valid empty view, not `NOT_ACTIVE`; cross-tenant isolation (a different tenant's organization never sees another tenant's connections); corrupted tenant file degrades to an empty view instead of throwing (the one novel guard).
- No change to `internal-os-view-state.ts`, `internal-os-request-handler.ts`, `internal-os-http-server.ts`, or `internal-os-render.ts` — the port, its threading into the real route, and its rendering were all already in place since Rev184 F3-residual/Rev195 F1. This checkpoint supplies only the missing production-shaped adapter.
- Full regression: **2875/2875 passing** (2870 pre-existing on PR #156's tip + 5 new), clean strict typecheck, zero new runtime dependency (only `node:fs`/`node:path`/`node:crypto` transitively via the already-accepted store).

## Guard-disable sanity

- The one novel guard (try/catch around `store.list` in `resolveView`) was disabled (the try/catch removed, the call made directly) and the suite rebuilt: exactly the "corrupted tenant file" adversarial test failed (surfacing the real `CorruptedConnectorConnectionFileError` uncaught, confirming the guard is load-bearing), and no other test regressed. The guard was then restored and verified byte-identical to the pre-edit source via `diff` before the final regression run.
- No second guard was added for cross-tenant isolation, since `FileDurableConnectorConnectionStore`'s own existing `validatePersistedConnectorConnection` already owns that guarantee (confirmed by direct inspection of its "cross-tenant record contamination" check) — adding a redundant filter here would not be guard-disable-sanity provable as load-bearing, which this corridor's own discipline treats as a reason not to add it.

## Explicitly deferred (not fabricated)

- **`OrganizationResourceBindingSource` still has no real adapter.** `resolveOrganizationResourceBindingStatus` requires assembling current memberships/service-principals/connections/project/config-policy-refs/worker-route-decisions/knowledge-evidence-refs — a multi-source composition this repository has no single existing "current evidence for an Organization" caller for. Building one is a materially larger packet than this one and risks inventing several new enumeration capabilities at once; left open for its own later-scoped checkpoint (or explicit Brain/Founder authorization naming it), not self-built here.
- **`task`/`quota`/`pendingApprovals`/`auditEvidence` dimensions remain unwired.** Each requires a per-job, per-wait-request, or per-evidence-item CALLER-known identity to resolve (per `composeOperationalObservabilityView`'s own doc comment), not an "enumerate all of them for this Organization" capability this repository has anywhere yet. Inventing one would repeat the exact "list customers for a tenant" problem `V2-ADMIN-SURFACE-001`/`CUS-OFFBOARD-DURABLE-001` both already declined to invent. Leaving them absent is not fabrication, since the composer's own contract already treats every dimension as independently optional/empty by construction.
- **Not wired into `internal-os-dev-main.ts`.** Mirrors `customer-offboarding-admin-source.ts`'s own precedent exactly: the one real dev-fixture caller in this repository has never wired any of the three optional admin-surface sources (`resourceBindingSource`/`operationalObservabilitySource`/`customerOffboardingAdminSource`); this checkpoint does not change that pattern on its own initiative.
