## Purpose (from the packet)

Implement the smallest provider-neutral upstream project-compilation slice that turns bounded sold scope/customer evidence plus a machine-readable blueprint into a complete, versioned, deterministically validated ProjectPlan/DAG and derived OutcomeJob specifications with lineage — closing the DEC-133 planning/completeness gap without building a generic workflow platform.

## Scope (Minimum Domain Objects)

- `OfferBlueprintVersion` / `BlueprintRequirement` (`src/domain/offer-blueprint.ts`) — provider-neutral, reusable requirement catalog. Construction validates requirementId uniqueness and proves the `dependsOn` graph is acyclic and free of dangling references (T5).
- `SoldScope` (`src/domain/sold-scope.ts`) — bounded commercial scope: which CONDITIONAL blueprint requirements are explicitly sold-in or sold-out. Tenant/project-scoped.
- `CustomerEvidenceItem` (`src/domain/customer-evidence.ts`) — typed FACT/HYPOTHESIS/UNKNOWN evidence references (locators, never raw secret/payload content), optionally tagged to a requirementId for lineage.
- `ProjectPlanVersion` / `PlanNode` / `RequirementDisposition` / `compilePlan` (`src/domain/project-plan.ts`) — the deterministic compiler. Disposition resolution: REQUIRED-necessity items are always REQUIRED; CONDITIONAL items are REQUIRED if sold-in, NOT_APPLICABLE if sold-out, UNKNOWN if the sold scope declares neither. A REQUIRED-resolved item whose dependency chain includes any non-REQUIRED node becomes BLOCKED (resolved recursively/memoized over the acyclic dependency graph, not just one level deep).
- `PlanValidationResult` / `validatePlan` (`src/domain/project-plan-validation.ts`) — independent completeness validation, re-derived from the blueprint rather than trusting the compiler's own output. COMPLETE only when every REQUIRED blueprint requirement has a REQUIRED plan node and no node anywhere is UNKNOWN or BLOCKED.
- `OutcomeJobSpec` / `deriveOutcomeJobSpecs` (`src/domain/outcome-job-spec.ts`) — one spec per REQUIRED-disposition node only; NOT_APPLICABLE/UNKNOWN/BLOCKED nodes are excluded from the committed job set.
- `ProjectPlanDiff` / `diffProjectPlans` (`src/domain/project-plan-diff.ts`) — deterministic added/removed/changed comparison between two versions of the same plan.
- `ApprovalReference` / `createApprovalReference` / `isApprovalValidForPlan` (`src/domain/approval-reference.ts`) — binds an approval to a plan's exact id/version/content-hash (SHA-256 over canonical JSON via `node:crypto`, no new dependency); invalidated by any material change.
- `WEBSITE_BUILD_v1` reference fixture (`src/fixtures/website-build-v1.ts`) — exactly one bounded blueprint/fixture proving the compiler end-to-end across discovery/evidence, content/IA, design/build, SEO/runtime QA, required access/connection declarations, working-artifact checkpoint, approval lineage, handover and verification.
