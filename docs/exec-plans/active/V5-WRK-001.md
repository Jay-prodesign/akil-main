## Goal

Provide a pure, side-effect-free routing-decision function that selects an authorized executor (and, where required, an independent reviewer) from a caller-declared registry of admitted workers, without ever calling a real provider/model API or letting cost/availability/position override policy.

## Scope (this checkpoint)

- `src/domain/worker-routing-policy.ts`:
  - `AdmittedWorker` — a caller-declared record: `workerId` (opaque string — no hard-coded vendor/model name anywhere in this module), `declaredCapabilityRefs`, `declaredToolRefs`, `declaredPolicyConstraintRefs` (both added in the Rev52 correction — see below), `trustStatus` (`ADMITTED` | `UNTRUSTED` | `REVOKED`), `availability` (`AVAILABLE` | `UNAVAILABLE` | `DEGRADED`), `maxRiskLevel` (`STANDARD` | `HIGH_RISK`), `authorityLevel` (`STANDARD` | `ELEVATED`, added in the Rev52 correction), `costWeight` (caller-supplied, opaque relative-cost figure), `evaluationEvidenceRef` (non-empty provenance pointer).
  - `resolveWorkerRoute(request)` — pure function. Fails closed (`InvalidWorkerRoutingRequestError`) only on malformed structural input (empty `requiredCapabilityRef`, invalid `riskLevel`/`requiredAuthorityLevel`, non-array `requiredToolRefs`/`requiredPolicyConstraintRefs`, or `HIGH_RISK`/`requiresIndependentReview` with no `reviewerCandidates` supplied at all). Selects the first candidate in caller-supplied order that is `ADMITTED`, `AVAILABLE`, declares the required capability plus every required tool/policy-constraint ref, carries non-empty evidence, meets the required `authorityLevel`, and (for `HIGH_RISK` work) is authorized for that risk level. When independent review is required, selects the first reviewer candidate meeting the same filter AND distinct from the selected executor. Any policy failure (no eligible executor, or no eligible independent reviewer) returns an explicit `REJECTED` decision with a reason — never a thrown error.

## Explicitly deferred (not invented)

No real provider/model API call, no worker registry persistence, no filesystem/network/child_process coupling — the module has **zero imports** and never reads the system clock (routing is fully deterministic from caller-supplied input alone, matching §6's "provider-specific memory is never canonical company memory"). No cost-based tie-breaking beyond caller-supplied candidate order (the module does not sort by `costWeight` itself — a caller choosing to present candidates cost-ascending is the caller's own ordering choice, not logic this module owns). No cross-worker capability negotiation, no automatic worker discovery/admission (that remains a separate, out-of-scope admission process this module only consumes the declared output of), no evaluation-evidence interpretation (the module requires `evaluationEvidenceRef` to be present, never reads or scores its contents).

## Architecture / semantic invariants (verified by test)

- A worker whose `trustStatus` is not `ADMITTED` is never selected as executor or reviewer, regardless of cost, position, or availability.
- A worker whose `availability` is not `AVAILABLE` is never selected — a caller degrading to a fallback candidate after an unavailable primary exercises the same uniform filter, never a relaxed one (§6: "provider outage degrades gracefully" without silently reducing requirements).
- A worker lacking the required capability, or lacking a non-empty `evaluationEvidenceRef`, is never selected.
- A worker whose `maxRiskLevel` is `STANDARD` is never selected for `HIGH_RISK` work.
- Candidate order is caller preference only (e.g. cost-ascending) — an ineligible, cheaper, earlier-listed worker never wins over an eligible, later-listed one.
- When independent review is required, the selected reviewer is always distinct from the selected executor — an executor is never permitted to review its own work through this function.
- Every returned decision (`ROUTED` or `REJECTED`) carries a non-empty `reason`.
- A worker missing any required tool ref, missing any required policy-constraint ref, or whose `authorityLevel` is below the route's `requiredAuthorityLevel` is never selected — as executor or reviewer, and never as a "relaxed" fallback (Rev52 correction).

## Hard Non-Scope

No filesystem/network/child_process import (verified by boundary scan — the module has zero imports at all); no provider/model hard-coding (no vendor/model name literal anywhere in source); no secret/credential material; no system-clock read (verified by boundary scan); no worker admission/registry mutation; no merge/deploy/release/production/publication/customer-binding/legal/financial action anywhere in this checkpoint's source.

## Rev52 correction (post-submission, same branch)

Brain Rev52 exact-head review of the original submission (evidence bound only to short head `c106161`) returned two findings:

- **F1 — required worker policy dimensions not modeled**: V5 R22 §6 requires each worker to have declared capabilities/**tools**/**policy constraints**/evaluation evidence, and requires **authority** to be modeled as a dimension distinct from admission and availability ("provider availability != admission != authority"). The original `AdmittedWorker` modeled capabilities/trust/availability/risk/cost/evidence but not tool access, policy/privacy-security constraints, or an explicit authority level — so a worker could be routed without ever proving those required dimensions. Fixed by adding `declaredToolRefs`, `declaredPolicyConstraintRefs`, and `authorityLevel` (`STANDARD` | `ELEVATED`) to `AdmittedWorker`, and `requiredToolRefs`, `requiredPolicyConstraintRefs`, and `requiredAuthorityLevel` to `WorkerRoutingRequest`; the eligibility filter (applied identically to executor and reviewer selection, and to every fallback candidate) now requires a worker to declare every required tool/policy-constraint ref and to meet or exceed the required authority level. 10 new adversarial tests (A23-A32) cover missing/partial tool refs, missing policy-constraint refs, insufficient/sufficient/higher authority levels, fallback-cannot-weaken, invalid-input fail-closed, and reviewer-side enforcement.
- **F2 — exact-head transferability gap**: the original evidence recorded only the abbreviated head `c106161`, not a full 40-character SHA, so Brain could not bind an exact-head review to it. Fixed by producing new evidence bound to the full pushed head SHA (see Evidence below) with complete raw command output.
