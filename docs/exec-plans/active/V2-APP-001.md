## Goal

Implement the minimum first-party, server-capable TypeScript web-application shell with a provider-neutral `AuthenticatedPrincipal`/`SessionContext`/`TenantContext` model, fail-closed route admission, and tenant/customer/project scope enforcement derived only from a trusted session — with no external identity provider, no persistence, and no production deployment — so that V2-CDO-006's own edge-stop predicate (an existing logged-in application shell / auth / session / tenant boundary) can be re-evaluated truthfully.

## Scope (Minimum Bootstrap, `src/web/`)

- `session-context.ts` — `AuthenticatedPrincipal`, `TenantContext`, `SessionContext`; `createAuthenticatedPrincipal`/`createSessionContext` factories. `TenantContext` is always derived from the given `principal`'s own `tenantId`/`customerId` — never independently caller-supplied.
- `session-provider.ts` — `SessionProvider` port (`resolveSession(token) -> SessionContext | undefined`).
- `production-session-provider.ts` — `createProductionSessionProvider()`: unconditionally returns `undefined` for any token. No real IdP integration exists to back anything else (A8).
- `dev-fixture-session-provider.ts` — `createDevFixtureSessionProvider({ fixtures, isProduction })`: throws `DevFixtureSessionProviderInProductionError` at **construction time** (not per-request) if `isProduction` is true; otherwise a deterministic in-memory token → `SessionContext` lookup (A7).
- `route-guard.ts` — `requireSession` (fail-closed on missing/invalid token, `UnauthenticatedError`), `requireTenantOwnership` (field-by-field tenant/customer/project match against the session's own scope, `TenantScopeMismatchError` on any mismatch, including a session-side `projectId` that is absent or different) (A4/A5).
- `snapshot-view-state.ts` — `ClientProjectSnapshotSource` port and `resolveProtectedSnapshotView`: checks tenant ownership **before** ever calling the snapshot source; maps to `FORBIDDEN_TENANT_SCOPE` / `NOT_FOUND` / `ERROR` / `READY` (A9/A10).
- `shell-render.ts` — `ShellPageContent` discriminated union (`LOADING`/`EMPTY`/`UNAVAILABLE`/`UNSUPPORTED`/`BLOCKED`/`ERROR`/`NOT_FOUND`/`UNAUTHENTICATED`/`FORBIDDEN_TENANT_SCOPE`/`READY`) and `renderShellPage`: one shared accessible HTML layout (skip link, semantic landmarks, viewport meta, `:focus-visible` outline, responsive breakpoint, always-visible text status label alongside a tone class) (A11/A12).
- `request-handler.ts` — `createRequestHandler`: pure `IncomingRequestLike -> OutgoingResponseLike` function with zero `node:http` dependency; rejects non-GET as `UNSUPPORTED`, parses `/portal/:tenantId/:customerId/:projectId`, enforces session/tenant checks, maps delivery status to the correct shell state.
- `http-server.ts` — `createHttpServer`: the only file importing `node:http`; translates a real socket request/response to/from the plain shapes and selects the fail-closed production provider whenever `isProduction` is true.
- `src/fixtures/web-shell.ts` — one deterministic dev-only session fixture scoped to the existing `WEBSITE_BUILD_v1` ownership tuple, and one fixture `ClientProjectSnapshotSource` backed by the existing verified `WEBSITE_BUILD_V1_CLIENT_PROJECT_SNAPSHOT` (V2-CDO-005) — no new domain identity invented.

## Architecture Invariants (per task head)

Web framework is an adapter, not a new domain authority; no external provider SDK/OAuth/token exchange/hosted auth product selected; no persistence/database/data-plane activation; `ClientProjectSnapshot` remains the sole customer-safe read boundary; visibility grants no approval/resume/verify/execute/mutate authority; framework/package choice is replaceable/portable with no hard-coded cloud/PaaS deployment; dev/test fixture auth is mechanically excluded from production; public-site (Shopify) and logged-in-app release gates remain independent.
