## Scope (this checkpoint)

`src/domain/service-catalog-admission.ts` — composing `commercial-order.ts`'s own unmodified `CommercialOrder`/`ServiceCatalogEntry`/`DeclaredServiceLookupResult` (type-only imports, never redefined) and `delivery-recipe.ts`'s `DeliveryRecipe`/`offer-blueprint.ts`'s `OfferBlueprintVersion` (type references only):

- **Admission gate**: `ServiceCatalogAdmission`/`admitServiceCatalogEntry` — the only construction path (no separate promotion step, mirroring `capability-admission.ts`). Fails closed unless `catalogEntry.recipeId` exactly matches the supplied `recipe.recipeId` (an admission can never bind a catalog entry to a recipe it does not actually declare), and requires non-empty `admittedByAuthorityId`, `evidenceRef`, and `admittedAt`.
- **Revocation**: `revokeServiceCatalogAdmission` — terminal, one-way (`ADMITTED` → `REVOKED` only), reusing `partner-capability-admission.ts`'s own Rev62 temporal-integrity discipline verbatim: `revokedAt` must not be strictly before `admittedAt` (equal accepted as immediate revocation).
- **Trusted resolution / gap behavior**: `TrustedServiceResolution`/`resolveTrustedServiceForOrder` — composes `resolveDeclaredServiceFromOrder`'s own output (never re-implemented) with the caller-supplied admitted catalog:
  - `UNRESOLVED_SERVICE` passes straight through unchanged when the declared lookup itself failed.
  - `RESOLVED` only when exactly one currently-`ADMITTED` admission matches the declared lookup's exact `blueprintId`/`blueprintVersion`/`recipeId` triple for that `serviceRef`.
  - `NOT_ADMITTED` — a first-class, honest disposition, never a thrown error and never conflated with `RESOLVED` — whenever a service is declared-resolvable but no matching admission exists, the only matching admission is `REVOKED`, or the only matching admission is bound to a different (stale/superseded) `blueprintVersion`.
  - Throws (never guesses a "closest" admission) on an ambiguous multi-admission match, matching `resolveDeclaredServiceFromOrder`'s own established convention.
- `tests/service-catalog-admission.test.ts` (16 tests: SA1-SA16) and `tests/svc-adm-001-boundary-scan.test.ts` (6 tests).

## Rev102 correction (exact head `bee3d2abc3d73fd9a67f0fb36e9227e85dd4f490`)

Brain's exact-head review returned `CHANGES_REQUIRED / BOUNDED` with two findings, both fixed on this same branch without redesign:

- **F1 TEMPORAL INTEGRITY**: `admittedAt`/`revokedAt` were validated only as non-empty strings, and revocation ordering was checked with lexicographic string comparison (`revokedAt < admittedAt`) — a malformed timestamp, or two equivalent instants expressed with different timezone offsets, could be accepted or misordered. Fixed by adding `requireValidTimestamp` (parses via `Date.parse`, returns `{ raw, ms }`), mirroring `partner-capability-admission.ts`'s own Rev62 fix exactly; every ordering comparison now uses the parsed `ms` value, never the raw string. New adversarial tests: SA5b/SA9b (malformed timestamp rejected), SA9c (a `revokedAt` with a different-but-equal-instant timezone offset is correctly accepted as immediate revocation, not wrongly rejected as "before"), SA9d (a `revokedAt` that is genuinely 30 minutes before `admittedAt` in real chronological time is rejected even though its raw string sorts *after* `admittedAt` lexicographically — verified with `Date.parse` arithmetic before writing the test: `"2026-01-01T00:30:00.000+01:00"` resolves to ms `1767223800000`, 30 minutes before `admittedAt`'s ms `1767225600000`, while the old buggy string comparison would have evaluated `false` on this exact pair).
- **F2 AUTHORITY CLAIM BOUNDARY**: `admitServiceCatalogEntry` accepted a bare caller-supplied `admittedByAuthorityId` string — a provenance *label*, never an actual admitted-authority decision, even though Family 1 explicitly requires a trusted/admitted service-catalog provenance/authority boundary. `ServiceCatalogEntry` has no tenant scope, so `authority.ts`'s tenant-bound `AuthorityContext` would misrepresent this as a tenant-scoped action; instead this reuses `worker-routing-policy.ts`'s existing, already-established, non-tenant-scoped admitted-identity/authority-level primitive (`AdmittedWorker`), exactly as `resolveWorkerRoute` itself already gates protected/high-trust-scope routes on `authorityLevel: "ELEVATED"`. `admitServiceCatalogEntry` now takes an `authorizingWorker: AdmittedWorker` and fails closed unless `trustStatus === "ADMITTED"` and `authorityLevel === "ELEVATED"`; the accepted worker's `workerId` is persisted as `admittedByAuthorityId` for audit (the field/shape on `ServiceCatalogAdmission` itself is unchanged). New adversarial tests: SA3 (rejects `UNTRUSTED`/`REVOKED` trust status), SA3b (rejects `STANDARD` authority level even when trusted), plus a boundary-scan test asserting both gate checks are present in source. No second IAM/global-authority model invented; `worker-routing-policy.ts` is a read-only type dependency, unmodified.

## Architecture / semantic invariants (verified by test)

- Admission: binds serviceRef/blueprint/version/recipe and authority/evidence correctly (SA1); rejects a `catalogEntry.recipeId`/`recipe.recipeId` mismatch (SA2); rejects an `authorizingWorker` that is not `trustStatus: "ADMITTED"` (SA3) or not `authorityLevel: "ELEVATED"` (SA3b) — Rev102 F2; rejects empty `evidenceRef` (SA4), empty (SA5) or malformed (SA5b) `admittedAt` — SA5b is Rev102 F1.
- Revocation: transitions to `REVOKED` with a recorded reason (SA6); fails closed on double-revoke (SA7); rejects a `revokedAt` strictly before `admittedAt` (SA8); accepts `revokedAt === admittedAt` (SA9); rejects malformed `revokedAt` (SA9b); chronological (not lexicographic) ordering across timezone offsets (SA9c/SA9d) — all Rev102 F1.
- Trusted resolution: passes through `UNRESOLVED_SERVICE` (SA10); resolves `RESOLVED` on an exact admitted match (SA11); the gap-behavior case — `NOT_ADMITTED` when declared-resolvable but unadmitted (SA12); never trusts a `REVOKED` admission (SA13); never trusts a stale-blueprint-version admission (SA14); throws on ambiguous multi-admission match (SA15); never substitutes a different serviceRef's admission (SA16).
