## Scope (Minimum Domain Objects)

- `DeliveryRecipe` / `createDeliveryRecipe` (`src/domain/delivery-recipe.ts`) — `recipeId`, immutable `version`, `jobFamily`, `requiredCapabilityRefs`, `requiredContextRefs`, `policyRefs`, `steps`, `gates`, `evidenceRequirements`, `completionRequirements`.
- `DeliveryRecipeStep` — `stepId`, `dependsOn` (step ids), `allowedWorkerRefs`/`prohibitedActions` (plain string references only — no provider/model implementation, no invocation config), `requiredGateRefs`, `requiredEvidenceRefs`, `recovery`.
- `DeliveryGate` — `gateId` + `type` (`CUSTOMER_INPUT` | `CUSTOMER_APPROVAL` | `HUMAN_REVIEW`). Reference/requirement only; grants no execution or resume authority.
- `DeliveryEvidenceRequirement` — `requirementId` + `evidenceClass` + `description`. No raw payload field.
- `RecoverySemantics` — `NO_EXTERNAL_EFFECT` | `IDEMPOTENT_RETRY` | `COMPENSATABLE` | `IRREVERSIBLE_MANUAL_RECONCILIATION` | `UNKNOWN_BLOCKED`, plus `isRetryableRecovery` (true only for `IDEMPOTENT_RETRY`) and `isProhibitedAction` (consults only `step.prohibitedActions`, never `allowedWorkerRefs`).

## Invariants

- Recipe version is immutable (a revision would create a new `DeliveryRecipe` value, never mutate one in place — no in-place mutation function is implemented or exposed).
- Step ids unique; `dependsOn` resolves; dependency graph acyclic (same construction-time validation pattern as `createOfferBlueprintVersion`'s requirement graph).
- Every `requiredGateRefs`/`requiredEvidenceRefs`/`completionRequirements` reference resolves against the recipe's own `gates`/`evidenceRequirements`.
- Every step has an explicit, required `recovery` classification; `UNKNOWN_BLOCKED` (and every classification other than `IDEMPOTENT_RETRY`) is fail-closed — `isRetryableRecovery` returns `false` for it.
- `allowedWorkerRefs`/`requiredGateRefs`/`requiredEvidenceRefs` are plain string/id references only — the type has no field capable of holding a provider/model implementation or invocation config, so vendor lock-in is structurally impossible.
- `isProhibitedAction` consults only `step.prohibitedActions` — listing an action in `allowedWorkerRefs` cannot remove it from the prohibited set (no code path connects the two).
- `DeliveryGate` carries only `gateId` + `type` — no field or function connects a gate to `OutcomeJob` state; `delivery-recipe.ts` has no import of `outcome-job.ts` and exports no `OutcomeJob`-transitioning function (verified by both a functional test and an import-statement boundary scan).
- A recipe cannot create a second `OutcomeJob` lifecycle or bypass existing verification/evidence semantics — this module defines a recipe only; it does not execute steps, dispatch workers, resolve gates, or touch `OutcomeJob`.
