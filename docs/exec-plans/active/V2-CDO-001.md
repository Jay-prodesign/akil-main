## Purpose

Implement the smallest concrete, provider-neutral, secret-free slice of "project/service status" and "unified delivery timeline" (v2.0 scope items 2–3) as a pure read-model projection over the already-VERIFIED/COMPLETED AKI-BE-001 domain kernel (`OutcomeJob`, `AuditEvent`, `Project`, `Customer`, `TenantScope`) — the customer-observable core a client portal would eventually render, built with zero new architecture, zero new dependency, and zero HTTP/frontend surface.

## Scope (Minimum Domain Objects)

- `DeliveryStatusLabel` / `DeliveryJobStatus` / `DeliveryStatusView` / `computeDeliveryStatus` (`src/domain/delivery-status.ts`) — aggregates a project's own `OutcomeJob` records into one customer-safe status label (`NOT_STARTED` / `IN_PROGRESS` / `BLOCKED` / `COMPLETE`) plus a per-job breakdown, derived directly from the existing canonical `OutcomeJobState` lifecycle (main path vs. the four exception states) — no new state machine invented.
- `DeliveryTimelineEntry` / `DeliveryTimeline` / `buildDeliveryTimeline` (`src/domain/delivery-timeline.ts`) — chronological (timestamp-sorted) projection of a project's own `AuditEvent` records into a minimal customer-facing entry shape (`eventId`, `jobId`, `eventType`, `timestamp`, optional `reason`); deliberately omits `relatedRefs` and any content-based redaction/visibility classification, since the canonical source defines no customer-visibility taxonomy for arbitrary `eventType` strings and inventing one would be an unsourced business rule.
- Both functions fail closed (throw) on any input record whose `tenantId` or `projectId` does not match the given `Project` — matching the DEL-003 T7 "cross-tenant/wrong-project ... binding fails closed" discipline already established in this repository.

## Non-Scope (explicitly not implemented this slice)

Client portal UI/frontend or any navigation/IA surface (Section 2 of the Master Release Plan classifies "client portal" as a major-version mental-model change requiring "mandatory IA/frontend review" — not something to build unilaterally in a backend-only bounded slice); AI Project Advisor (requires AI/model routing, explicitly stage/trigger-gated per `CURRENT_STATE.md`); structured Delivery Recipes (requires AI-004, stage-gated); customer communications routing (requires an external provider/connector, CONN-001, stage-gated); AI Commerce capability consumption (explicit cross-project boundary, requires an authorized integration contract); account/customer ownership as a distinct authority model beyond the existing `Customer`/`TenantScope` primitives already in AKI-BE-001; any HTTP/API server, database, queue, or deployment infrastructure (this remains a domain/application kernel); any customer-visibility/redaction classification for `AuditEvent.eventType` beyond the minimal field set exposed by `DeliveryTimelineEntry`.
