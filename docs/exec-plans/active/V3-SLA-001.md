## Architecture / semantic invariants

- `internalAttentionLevel` is computed only from `job.state` — `ESCALATED` maps to `ESCALATED`; `BLOCKED`/`RECOVERING`/`STOPPED` map to `EXCEPTION`; everything else maps to `NORMAL`. No other input influences this classification.
- `contractualSlaStatus` is always `"UNKNOWN"` — a single-literal type, so this module is structurally incapable of ever claiming a known contractual commitment (§7: "internal operating target and customer-contractual SLA are separate truths" / "missing/unknown commitment remains unknown").
- `reason`/`timestamp` are surfaced only when `internalAttentionLevel !== "NORMAL"` — a resolved exception's old reason/timestamp is never shown as if the job were still in that state (§7: "stale/unsupported SLA states cannot appear as current contractual truth," applied here to internal state for the same reason).
- A caller-supplied `latestExceptionEvent` must belong to the exact same `jobId`/`tenantId` as the given `job`, or construction rejects (fail-closed cross-job contamination check).
- `responsibleOwnerMembershipId` reuses `resolveCurrentOwner` (V3-OWN-001) verbatim rather than re-deriving ownership; it is `undefined` when no `DELIVERY_OWNER` assignment exists — a legitimate "unknown/unassigned" state, never guessed.
- This module imports `outcome-job.ts` as **types only** (`OutcomeJob`, `OutcomeJobState`) — no create/transition function — and imports nothing from `authority.ts`, so constructing or reading an `AttentionState` cannot itself transition an `OutcomeJob` or grant any permission (§7: "escalation visibility does not create execution/approval authority").
- No `next-safe-action` field exists on `AttentionState` at all — no source for it exists anywhere in this repository, so it is honestly omitted rather than fabricated (§7 says "where available"; it is not available in this slice).
