## Scope (this checkpoint)

`src/domain/local-execution-bridge.ts` — the pure protocol/domain contract layer for §17's control channel, composing L0's own `local-execution.ts` contracts (`DeviceRegistration`, `DevicePolicy`, `LocalTaskLease`, `LocalTaskCheckpoint`, `markDeviceOnline`, `isWorkspaceRootAllowed`) without modifying or duplicating any of them:

- **Protocol envelope + message families (§17)**: `BridgeProtocolMessageKind` (the exact nineteen families named in the packet, no others), `BridgeProtocolEnvelope` (`protocolVersion` + tenant/device/worker/task/run identity as applicable + monotonic `eventSeq` + idempotent `messageId`), `validateBridgeProtocolEnvelope` (fail-closed structural validation), `isRecognizedBridgeMessageKind`, `SUPPORTED_BRIDGE_PROTOCOL_VERSIONS` (§16's "capability negotiation prevents incompatible clients from silently running").
- **Replay/idempotency (§17 "following existing AKILTA durability lessons")**: `BridgeDeviceReplayState`/`validateBridgeMessageReplay` — a device's first message bootstraps its replay state; every subsequent message must carry a strictly greater `eventSeq`; an exact `messageId` repeat (at-least-once redelivery after a reconnect) is recognized as an idempotent `DUPLICATE`, never a silent double-apply or a hard failure.
- **One-time enrollment (§17 ENROLL_CHALLENGE/ENROLL_PROOF)**: `EnrollmentChallenge`/`createEnrollmentChallenge` (only issuable to a `PENDING` device) and `completeDeviceEnrollment`, which composes the existing, unmodified `markDeviceOnline` transition — no second device-status graph. Fails closed on a proof referencing a foreign/stale challenge, a challenge issued to a different device, an expired challenge, or a device that is no longer `PENDING` (including a challenge already redeemed once).
- **Bridge connection lifecycle (§21 "disconnect/reconnect")**: `BridgeConnectionState` (`DISCONNECTED`/`CONNECTING`/`CONNECTED`/`RECONNECTING`) with a strictly closed transition graph — `DISCONNECTED` can only move forward through `CONNECTING`; a lost `CONNECTED` session moves to `RECONNECTING` (never straight back to `CONNECTING`) and either resumes or gives up.
- **Heartbeat (§17 HEARTBEAT + §16 "revoked ... fails closed")**: `processBridgeHeartbeat` — accepted only from a device currently `ONLINE` (rejected outright for `REVOKED`/`QUARANTINED`/`OFFLINE`/`PENDING`, before replay validation even runs), still subject to the same replay/idempotency discipline as every other message.
- **Allowlisted workspace manager (§16/§21)**: `resolveAllowedWorkspacePath` composes L0's own unmodified `isWorkspaceRootAllowed` (no second allowlist check) and additionally fails closed on a `..` traversal segment or a leading-`/` absolute-path escape inside an otherwise-allowed root. Pure path algebra only — this module never touches the real filesystem.
- **Lease/checkpoint message consistency (§17/§21 "lease/checkpoint/event persistence")**: `validateLeaseMessageEnvelope`/`validateCheckpointMessageEnvelope` — a wire message can never silently reference a lease/checkpoint it does not structurally match (device/worker/task identity). This is a pure consistency guard, not new lease semantics; the lease/checkpoint state machine remains exclusively `local-execution.ts`'s own.
- **Device key + control-channel ports (§21 "device key generation/storage abstraction"; §17 "transport-independent at domain level")**: `DeviceKeyMaterial`/`DeviceKeyStore` and `BridgeControlChannel` — ports only, no real key-generation library or streaming-socket implementation anywhere in this module or repository (boundary-scan test asserts this), mirroring `LocalWorkerAdapter`'s own established port-only discipline from L0.

## Architecture / semantic invariants (verified by test)

- A structurally malformed envelope (unsupported `protocolVersion`, unrecognized `kind`, non-integer/negative `eventSeq`, empty identity field) is rejected before any replay or business validation runs (B2-B5).
- Replay/idempotency: a device's first message always bootstraps (B7); a strictly greater `eventSeq` advances state (B8); an equal-or-lower `eventSeq` fails closed as a replay attack, sanity-checked (B9); an exact `messageId` repeat is a recognized `DUPLICATE`, not a double-apply (B10); replay state from a different device is rejected (B11).
- Enrollment: a challenge can only be issued to a `PENDING` device (B13) with `expiresAt` strictly after `issuedAt` (B14); completion fails closed on a foreign/forged `challengeId` (B16, sanity-checked), a challenge issued to a different device (B17), an expired proof (B18), or a second redemption attempt against an already-enrolled device (B19); a genuinely matching, timely proof transitions `PENDING` → `ONLINE` via the unmodified `markDeviceOnline` (B15).
- Connection lifecycle: the full DISCONNECTED→CONNECTING→CONNECTED→RECONNECTING→CONNECTED→DISCONNECTED cycle is provable (B20); `DISCONNECTED` can never jump directly to `CONNECTED`/`RECONNECTING` (B21); `CONNECTED` can never fall straight back to `CONNECTING` (B22).
- Heartbeat: accepted and replay-advances state from an `ONLINE` device (B23); rejected outright from `REVOKED` (B24) or `QUARANTINED` (B25) devices, before replay validation runs; rejected for a non-`HEARTBEAT` envelope (B26) or a cross-device envelope/device mismatch (B27).
- Workspace path resolution: resolves correctly under an allowed root (B28); rejects an unauthorized root (B29); rejects a `..` traversal segment even under an allowed root, sanity-checked (B30); rejects an absolute-path `relativePath` (B31); fails closed once the device policy's kill switch is engaged (B32).
- Lease/checkpoint message consistency: a correctly-addressed `LEASE_OFFER`/`LEASE_ACCEPT`/`LEASE_REJECT` is accepted (B33); a forged `workerId` reference is rejected (B34); a non-lease-family `kind` is rejected (B35); a correctly-addressed `CHECKPOINT` is accepted (B36); a checkpoint that does not belong to the given lease is rejected (B37).
- Sanity-checked: three representative adversarial guards (B9's replay-strictly-greater check, B16's foreign-challenge-id check, B30's path-traversal check) were each temporarily disabled and the build/tests rerun — exactly those three tests failed, with every other test (including the positive B6/B15/B28 cases proving the guards don't over-reject) still passing; the guards were then restored and 802/802 reconfirmed.
