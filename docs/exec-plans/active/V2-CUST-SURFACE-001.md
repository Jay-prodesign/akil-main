## Scope (this checkpoint)

- New `src/domain/customer-lifecycle-readiness.ts`: `projectCustomerLifecycleReadiness`, a pure, zero-persistence composition of an already-accepted `CustomerOffboardingRequest` (optional) and `CustomerOffboardingExecutionState` (optional) into one customer-safe `CustomerLifecycleReadinessProjection`, mirroring `subscription-usage-status.ts`'s own composition discipline exactly. `offboardingStatus` defaults to `"NOT_REQUESTED"` when no request is supplied — never inferred. `backupReadiness` is honestly `"AVAILABLE"` (declared as its own closed union, not a bare boolean, so a future genuinely-absent state never requires a breaking change). Fail-closed ownership checks: a foreign/mismatched `offboardingRequest` is rejected; an `offboardingExecution` can only be supplied alongside its own `offboardingRequest`, and must reference that exact request (by `requestId`) and the same tenant/customer.
- Three new web-layer ports + resolvers, each cloning `team-attention-view-state.ts`'s exact discipline:
  - `src/web/customer-commercial-view-state.ts` (`CustomerCommercialStatusSource`/`resolveProtectedCustomerCommercialStatusView`) over `SubscriptionUsageStatus`.
  - `src/web/billing-reference-view-state.ts` (`BillingReferenceStatusSource`/`resolveProtectedBillingReferenceStatusView`) over `BillingReferenceRecord`.
  - `src/web/customer-lifecycle-readiness-view-state.ts` (`CustomerLifecycleReadinessSource`/`resolveProtectedCustomerLifecycleReadinessView`) over `CustomerLifecycleReadinessProjection`.
- `src/web/shell-render.ts` extended with three new, distinctly-named, always-visible sections ("Subscription & entitlement", "Billing reference", "Account lifecycle") — rendered only on `READY`/`BLOCKED`, exactly as scoped as the existing team-attention section. Each renders an honest `Unavailable` message when its view is absent/`UNAVAILABLE`/`FORBIDDEN_TENANT_SCOPE` (the three are never distinguished from each other in the rendered page, so no boundary detail leaks). No monetary amount is ever rendered (the underlying `BillingReferenceRecord` carries none). No mutating upgrade/cancel/offboard control (button/form/input) is rendered anywhere in these sections — verified by test. The pre-existing, textually-distinct "Commercial: Unavailable — pending separate commercial-authority checkpoint" line inside the team-attention section (about commission/discount authority, a different concept) is deliberately left untouched.
- `src/web/request-handler.ts` extended with three new optional deps (`commercialStatusSource?`, `billingReferenceStatusSource?`, `lifecycleReadinessSource?`), each resolved alongside the existing `teamAttentionSource` resolution (same point in the READY branch, after the `NOT_STARTED` → `EMPTY` check) and threaded into both the `BLOCKED` and `READY` `ShellPageContent`.
- `src/fixtures/web-shell.ts` extended with three new fixture sources (`createWebShellFixtureCommercialStatusSource`, `createWebShellFixtureBillingReferenceStatusSource`, `createWebShellFixtureLifecycleReadinessSource`), each scoped to the existing `WEBSITE_BUILD_V1_OWNERSHIP` tuple, mirroring `createWebShellFixtureTeamAttentionSource`'s own pattern.
