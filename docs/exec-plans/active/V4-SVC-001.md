## Explicitly deferred (not invented)

Of §5's seven distinct dimensions ("service/customer outcome, required capability, admitted capability, provider support, entitlement, delegated authority and execution maturity"), this checkpoint represents only **required capability** (reused from `CapabilityAdmission`) and **execution maturity** (capped at the honest floor). **Entitlement** and **delegated authority** are not modeled — no canonical source in this repository specifies how they compose with capability admission, and inventing that composition would be fabricating policy. `MANUAL`/`PROVIDER_NATIVE`/`ENGINEER_ASSISTED`/`DIAGNOSE`/`RECOMMEND`/`DRAFT_PREVIEW`/`APPROVAL_REQUIRED`/`CONTROLLED_APPLY` are declared on `ExecutionMaturity` but not producible until real adapters (V4 §7 Workstream C) exist. **Provider support** is now represented at the one honest granularity this repository has — the existing `ConnectionBinding.connectionState` (see "Rev28 bounded correction" below) — rather than left entirely unmodeled. Timestamp-based staleness detection remains out of scope — `CapabilityAdmission`/`ConnectionBinding` carry no timestamp field in this repository, so there is no data to detect staleness from by wall-clock; this is a disclosed gap, not a silent omission.

## Rev28 bounded correction (2026-09-02) — CHANGES_REQUIRED_SOURCE_SEMANTICS

Brain Handoff Rev28 (independently fresh-read, `modifiedTime` advanced past Rev27) found: "Current routing can promote `VERIFIED_AVAILABLE` to `READ_ONLY` without authoritative freshness or provider/connectivity truth, and does not carry the required fallback/degradation semantics. A stale or unproven admission therefore cannot be proven fail-closed against V4 Workstream A." Required bounded correction: "make freshness and provider/connectivity/degradation semantics explicit and truthful; absent authoritative proof must not be promoted to current/executable; fail closed on explicit capability/provider reference mismatch where such refs exist; add regression coverage for stale/unknown admission and reference mismatch."

**Fix:** `resolveServiceCapabilityRoute` now accepts an optional `connectionBinding: ConnectionBinding` (type-only import from `connection-authority.ts` — still no create/transition/verify mutation function pulled in). `READ_ONLY` is now reachable only when all of the following hold: (1) `admission.status === "VERIFIED_AVAILABLE"`, (2) a `connectionBinding` was supplied, (3) its ownership tuple matches the given `ownership`, (4) its `connectionBindingId` exactly matches `admission.connectionBindingId` (fail-closed on capability/provider reference mismatch — a different, unrelated binding can never be substituted), and (5) its `connectionState` is currently `"VERIFIED"`. Any other case — no binding supplied, ownership mismatch, id mismatch, or `connectionState` of `REQUESTED`/`CONNECTED_UNVERIFIED`/`DEGRADED`/`REVOKED`/`HANDOVER_COMPLETE` — resolves `UNAVAILABLE` with a reason naming the exact cause. This makes provider-connectivity/degradation truth explicit (the binding's live `connectionState` is the source of currentness, not an immutable admission snapshot) without inventing a timestamp field that does not exist anywhere in this repository.

This correction moved the PR's exact head; a new complete exact-head evidence package was produced for the new head (see "Evidence" below and the Drive bridge).

## Architecture / semantic invariants

- `resolveServiceCapabilityRoute` imports only **types** from `capability-admission.ts` and `connection-authority.ts` — no create/promote/transition/verify function — so this module structurally cannot mutate or promote a `CapabilityAdmission` or `ConnectionBinding`.
- The given `admission`'s ownership tuple must exactly match the given `ownership` scope, or construction throws `InvalidServiceCapabilityRouteError` — fail-closed cross-tenant/cross-project substitution, same pattern as every other slice this checkpoint train. The optional `connectionBinding`'s own ownership tuple is independently checked against the same scope (Rev28) — a foreign-project binding fails closed even if its `connectionBindingId` happens to match.
- `UNVERIFIED`/`UNSUPPORTED`/`INELIGIBLE` all resolve `UNAVAILABLE` — never executable, regardless of any other input.
- `VERIFIED_AVAILABLE` resolves `READ_ONLY` only when a matching, currently-`VERIFIED` `ConnectionBinding` is supplied (Rev28 bounded correction) — never a higher rung, and never `READ_ONLY` from the admission snapshot alone — verified statically by a boundary-scan test that greps every `executionMaturity: "..."` assignment in source and asserts each is `UNAVAILABLE` or `READ_ONLY`.
- `reason` always cites the exact admission status and (when relevant) the exact connection-binding cause the decision was made from (provenance, §5).
- No import of `authority.ts` or `outcome-job.ts`, and nothing from `src/web/`/`src/application/`.

## Hard Non-Scope

No real provider/connection adapter (read, diagnose, recommend, draft-preview, apply); no provider SDK/OAuth/credential; no entitlement or delegated-authority model; no `DIAGNOSE`/`RECOMMEND`/`DRAFT_PREVIEW`/`APPROVAL_REQUIRED`/`CONTROLLED_APPLY` production; no persistence/database; no HTTP/UI surface; no AI Commerce mutation; no merge/deploy/release/production/publication/customer-binding/legal/financial action anywhere in this checkpoint's source.
