## Invariants

- Ownership must match the given `Project`'s own tenant/customer/project identity; a mismatch rejects before any computation (P2).
- The projection is read-only: it calls no `OutcomeJob`/`ProjectPlanVersion`/`ConnectionBinding`/`CapabilityAdmission` transition, verification, or admission function — only `computeDeliveryStatus`, `buildDeliveryTimeline`, and `isApprovalValidForPlan`, none of which mutate anything (P10).
- `nextAction` is derived only from the most recent `ProjectCommunicationRecord` with `classification === "ACTION_REQUIRED"`; `requiredActor: "CUSTOMER"` yields `CLIENT_ACTION_REQUIRED`, `"AKILTA"` yields `AKILTA_ACTION_REQUIRED`; absent any such record, it is explicitly `NO_ACTION_NEEDED` — routine internal engineering work can never manufacture a client action (P6/P7).
- `eta` is always the explicit `{ status: "UNKNOWN" }` literal; no invented date/percentage is structurally possible (P8).
- `workingArtifact.isCurrentVersionApproved` reuses `isApprovalValidForPlan` verbatim, so a materially changed "same version number" plan or a newer version never silently inherits a stale approval; `lastApprovedVersion` remains independently readable (P4/P5).
- `capabilities` exposes only `requiredCapabilityRef` + `status` — never `connectionBindingId`, `evidenceRef`, provider/workspace reference, or delegated-scope detail (P9).
- `recentCommunications` passes through `ProjectCommunicationRecord` values unmodified; `RECORDED_ONLY`/`DELIVERY_UNVERIFIED` records are never altered to appear delivered (P12).
- Cross-tenant/cross-project ownership on any input (jobs, plan, communication history, capability admissions) fails closed.
- Pure construction has no external effect.
